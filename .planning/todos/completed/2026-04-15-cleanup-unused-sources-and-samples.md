## Problem

プロジェクト初期〜各フェーズで試作した検証コード・サンプルスクリプト・参照用に残した外部スニペットなどが整理されないまま蓄積している。以下が読者・新規参加者の混乱や保守負荷になる:

- 現在は参照されていないモジュール・関数
- 各フェーズで作ったワンショットの検証スクリプト
- 旧実装を差し替えた際に削除し忘れたファイル
- `static/` や `scripts/` 直下の古いユーティリティ
- `docs/`・`.planning/` 以下の重複ドキュメント
- `tests/` の廃止された fixture / サンプル

## Solution

リポジトリを棚卸しして、以下の手順で片付ける:

1. **未参照コード検出**
   - `vulture` で Python のデッドコード検出
   - `knip` / `ts-prune` / `depcheck` でフロントの未使用 export と依存検出
   - `rg` で import / 参照が 0 件のファイル列挙
2. **サンプル・検証コード整理**
   - `scripts/` 直下のワンショットスクリプトに用途コメント追加 or 削除
   - 旧 SuperAgent 系サンプル（`sample_*`, `playground_*` 相当）の要否判定
3. **静的ファイル整理**
   - `static/` 以下で現在ロードされていないファイルを削除
4. **ドキュメント整理**
   - `docs/` の古い手順書・重複情報をアーカイブ
   - `.planning/` の quick-* completed で参照されなくなった中間成果物の削除判断
5. **テスト整理**
   - 廃止された fixture / skip されたまま放置のテストを整理
6. 削除は PR 単位で小分けにし、CI と動作確認を挟む

影響範囲が広いため、まず「棚卸しレポート」を作ってから削除 PR に分割する進め方が安全。関連 ADR（設計判断の変遷）と照合しつつ進める。
