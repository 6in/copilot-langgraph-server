  <action>
1. Create `frontend/Dockerfile`:
   - Use `node:22-alpine` as base image (lightweight, LTS)
   - Set `WORKDIR /app`
   - Copy `package.json` and `package-lock.json` (if exists, use wildcard `package*.json`)
   - Run `npm install`
   - Copy the rest of the frontend source
   - Expose port 5173
   - CMD: `npm run dev -- --host 0.0.0.0` (--host required for Docker container access)

2. Update `frontend/vite.config.ts`:
   - Add `server.host: '0.0.0.0'` so Vite binds to all interfaces inside the container (alternative to --host flag, but --host in CMD is sufficient; skip this if using CMD approach)
   - Actually, keep it simple: use `--host` in CMD only, no vite.config changes needed

3. Update `docker-compose.yml` — add `frontend` service:
   ```yaml
   frontend:
     build:
       context: ./frontend
       dockerfile: Dockerfile
     ports:
       - "5173:5173"
     volumes:
       - ./frontend:/app
       - /app/node_modules    # anonymous volume to preserve container's node_modules
     environment:
       - VITE_API_URL=http://api:8000
     depends_on:
       - api
   ```

   IMPORTANT for the Vite proxy: The current vite.config.ts proxies `/api` to `http://localhost:8000`. Inside Docker, the API is at `http://api:8000` (service name). We need to update `vite.config.ts` to use an environment variable or change the target.

   Since Vite config runs at build time (not runtime env), the simplest approach:
   - Update `vite.config.ts` proxy target to `process.env.VITE_API_TARGET || 'http://localhost:8000'`
   - Set `VITE_API_TARGET=http://api:8000` in docker-compose environment

   Wait — `process.env` in vite.config.ts works because vite.config.ts runs in Node.js context, not browser. But VITE_ prefix vars are for client-side. Use a non-VITE_ prefixed env var for server config:
   - Use `API_TARGET` env var (no VITE_ prefix since this is server-side proxy config)
   - In vite.config.ts: `target: process.env.API_TARGET || 'http://localhost:8000'`
   - In docker-compose: `environment: - API_TARGET=http://api:8000`

4. Update `frontend/vite.config.ts`:
   - Change proxy target from hardcoded `'http://localhost:8000'` to `process.env.API_TARGET || 'http://localhost:8000'`
   - This preserves local dev behavior (defaults to localhost) while allowing Docker override

5. Also update `app/api/main.py` CORS origins to include the Docker frontend origin. Inside Docker network, the frontend is accessed from the host at `http://localhost:5173`, which is already in the CORS list. No change needed.
