# Quick 260401-t47: Add loadThreads() After Job Completion — Summary

**One-liner:** Added `await loadThreads()` at all 3 job completion points in `sendMessage()` so the sidebar thread list refreshes automatically when a new thread's first checkpoint is written.

## What Was Done

When a user sends the first message in a new conversation, a thread is auto-created but only appears in `GET /api/threads` after the LangGraph job completes and the first checkpoint is written. Previously, the sidebar never refreshed at job completion, so the thread stayed invisible until a manual page reload.

Three `await loadThreads()` calls were added to `static/app.js`:

1. **Immediate done path** (line ~379): Inside the `if (immediate.status === 'done')` block, after `appendMessage('ai', immediate.result || '')`.

2. **SSE onmessage done path** (line ~403): Inside the `if (status === 'done')` block in `es.onmessage`, after the appendMessage/error block.

3. **Polling done path** (line ~443): Inside the `if (job.status === 'done')` block in `startPolling`, after `appendMessage('ai', job.result || '')`.

All 3 calls are placed after displaying the AI response but before re-enabling user input, ensuring the sidebar is refreshed before the user can send the next message.
