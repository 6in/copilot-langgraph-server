## Background

Phase 39 で worktree 並列実行 (`isolation="worktree"`) を使った際、`.claude/worktrees/agent-*` 配下に大量のファイルが作成・削除された。これを dev server が picked up し、2 つの障害が発生した:

1. **uvicorn `--reload` のリロード暴発**: 60 秒で 136 reload events。リロード中の POST `/api/threads` が 401 Unauthorized を連発 → frontend が認証失敗と判断して JWT cookie を失効させ、ログイン画面に redirect された。
2. **Vite WatchFiles の transform キャッシュ破損**: 並行更新で内部 module graph が壊れ、Phase 39 マージ前の transform 結果を保持。`docker compose restart frontend` するまでブラウザに古いバンドルが配信され続けた (AskMe ボタンが描画されない症状で発覚)。

両障害とも `.claude/worktrees/` を watch から除外すれば根本解決する。

## Goal

`.claude/worktrees/` (および周辺の noise source) を以下から watch 除外:

- **api**: `docker-compose.yml` の uvicorn `--reload` に `--reload-exclude` を追加
- **frontend**: `frontend/vite.config.ts` の `server.watch.ignored` を追加

worker (arq) と mcp-server は `--reload` を使っていないので変更不要。

## Tasks

### Task 1: docker-compose.yml の api service に reload-exclude を追加

ファイル: `docker-compose.yml` L72

変更前:
```yaml
command: uv run uvicorn app.api.main:app --host 0.0.0.0 --port 8000 --reload
```

変更後:
```yaml
command: uv run uvicorn app.api.main:app --host 0.0.0.0 --port 8000 --reload --reload-exclude '.claude/*' --reload-exclude '.planning/*' --reload-exclude 'frontend/*' --reload-exclude 'node_modules/*' --reload-exclude '__pycache__/*' --reload-exclude '*.pyc'
```

除外パスの根拠:
- `.claude/*` — 今回の root cause (worktree dir)
- `.planning/*` — GSD planning artifacts (docs only、コード再ロード不要)
- `frontend/*` — Vite が担当、api 側は watch 不要
- `node_modules/*` — frontend bind-mount のため container 内に存在し得る
- `__pycache__/*` / `*.pyc` — Python compile artifacts (再ロードのループ防止)

Verify: `docker compose up -d api` 後、`.claude/worktrees/dummy.txt` を作成して `docker compose logs api --since 5s | grep -c WatchFiles` が 0 件であることを確認。

### Task 2: frontend/vite.config.ts に server.watch.ignored を追加

ファイル: `frontend/vite.config.ts`

`server:` ブロック内に `watch.ignored` を追加。配列で複数パターンを除外。

変更後 (server オブジェクトのトップに追加):
```ts
server: {
  watch: {
    ignored: [
      '**/.claude/**',
      '**/.planning/**',
      '**/.git/**',
      '**/node_modules/**',
    ],
  },
  proxy: { ... }, // 既存
},
```

除外パスの根拠:
- `.claude/**` — 今回の root cause
- `.planning/**` — GSD planning artifacts
- `.git/**` — Vite default では除外されているが明示
- `node_modules/**` — Vite default だが明示 (chokidar の挙動を予測可能に)

Verify: `docker compose restart frontend` 後、Vite が正常起動し http://localhost:5173/orochi/ が 200 を返すこと。

### Task 3: api + frontend container 再起動 + smoke test

```bash
docker compose restart api frontend
sleep 5
# health check
curl -s -o /dev/null -w "api: %{http_code}\n" http://localhost:8000/health/agents
curl -s -o /dev/null -w "frontend: %{http_code}\n" http://localhost:5173/orochi/
# verify reload-exclude actually filters worktree noise (negative test)
touch .claude/worktrees/agent-aabe3c19/.dummy-test-file
sleep 3
echo "WatchFiles events (should be 0):"
docker compose logs api --since 5s | grep -c WatchFiles
rm .claude/worktrees/agent-aabe3c19/.dummy-test-file
```

成功条件:
- api: 200
- frontend: 200
- WatchFiles event count: 0 (`.claude/worktrees/` 内のファイル変更で api がリロードしないこと)

## Must Haves

- `docker-compose.yml` に `--reload-exclude '.claude/*'` 追加
- `frontend/vite.config.ts` に `server.watch.ignored` で `**/.claude/**` 追加
- Smoke test 3 件 (api health / frontend / worktree noise filtered) 全 PASS

## Out of Scope

- worker / mcp-server (現状 reload 使っていない)
- nginx / production 設定 (本変更は dev 専用)
- Vite の HMR キャッシュ自体の修正 (本変更はトリガーの noise を抑える、HMR バグ自体は別案件)
