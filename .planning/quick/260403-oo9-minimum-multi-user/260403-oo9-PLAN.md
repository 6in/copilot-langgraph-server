**POST /api/chat (send_message):**
1. After the arq enqueue call, upsert `thread_labels` with the user's `github_login`. Extract `github_login` from the JWT payload (add `get_jwt_payload` as a second dependency, or extract from the existing JWT decode path).
2. Specifically: after `await arq_redis.enqueue_job(...)`, do a psycopg upsert:
   ```sql
   INSERT INTO thread_labels (thread_id, label, github_login)
   VALUES (%s, %s, %s)
   ON CONFLICT (thread_id)
   DO UPDATE SET github_login = COALESCE(thread_labels.github_login, EXCLUDED.github_login),
                 updated_at = now()
   ```
   Use the thread_id from body, a default label like `"Chat {datetime UTC}"`, and the github_login from JWT.
   The COALESCE ensures an existing owner is not overwritten (first writer wins).
3. Add `request: Request` is already a parameter; use `request.app.state.db_uri` for the connection.
