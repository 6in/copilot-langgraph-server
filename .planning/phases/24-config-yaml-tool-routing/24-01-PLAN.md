# Plan 1: ToolRegistry + mcp_tools.yaml + worker startup 統合

## Goal
`config/mcp_tools.yaml` に MCP ツールカタログを宣言し、`ToolRegistry` クラスが worker 起動時に YAML と MCP サーバー実ツールリストの完全一致を検証する仕組みを実装する（MCP-03）。

## Context
Phase 23 までで `ping` / `web_search` / `db_query` / `claude_code` の 4 ツールが MCP サーバーに実装済み。Phase 24 では (1) これらをカタログとして YAML に宣言し、(2) `ToolRegistry` クラスで worker 起動時にバリデーションを行うことで、デプロイ後の無言不整合を防止する。CONTEXT.md D-03 の仕様に従い、不一致は **worker 起動失敗（RuntimeError 伝播）** とする。docker-compose.yml の変更は不要（worker サービスに `./config:/app/config:ro` マウントが Phase 18 から既存）。

**重要な設計判断（RESEARCH.md Pitfall 1）:** 既存の `worker.py startup()` の MCP 初期化ブロック全体が `try/except Exception` で囲まれている。`ToolRegistry.validate()` を try ブロック内に置くと RuntimeError が DEGRADED として握りつぶされる。よって **try/except の外** に配置し、RuntimeError を素直に伝播させる。

```python
"""Phase 24: MCP ツールカタログ + バリデーション (MCP-03).

D-03/D-04 per .planning/phases/24-config-yaml-tool-routing/24-CONTEXT.md.
config/mcp_tools.yaml で宣言したツール名と MCP サーバーが提供する実ツールリストの
完全一致を worker 起動時に検証する。不一致は RuntimeError で worker 起動を失敗させる。
"""
from __future__ import annotations

import yaml
from langchain_core.tools import BaseTool


class ToolRegistry:
    """MCP ツールカタログのバリデーションレジストリ。

    Usage:
        registry = ToolRegistry("config/mcp_tools.yaml")
        await registry.validate(mcp_tools)  # raises RuntimeError on mismatch
    """

    def __init__(self, yaml_path: str) -> None:
        with open(yaml_path) as f:
            cfg = yaml.safe_load(f) or {}
        self._expected: frozenset[str] = frozenset(
            entry["name"] for entry in (cfg.get("tools") or [])
        )

    async def validate(self, mcp_tools: list[BaseTool]) -> None:
        """YAML カタログと MCP 実ツールリストを照合。不一致なら RuntimeError。

        D-03: 双方向チェック。
          - YAML にあるが MCP が提供しない → 起動失敗
          - MCP が提供するが YAML にない → 起動失敗
        """
        actual: frozenset[str] = frozenset(t.name for t in mcp_tools)
        missing = self._expected - actual
        extra = actual - self._expected
        if missing or extra:
            raise RuntimeError(
                "[ToolRegistry] mcp_tools.yaml と MCP サーバーのツールリストが不一致。"
                f" YAML のみ: {sorted(missing)}, MCP のみ: {sorted(extra)}"
            )

    def expected_tool_names(self) -> frozenset[str]:
        """YAML で宣言された期待ツール名集合を返す。"""
        return self._expected
```

**重要:** Pitfall 1（RESEARCH.md）を回避するため、`ToolRegistry.validate()` は `try/except Exception` の **外側** に配置する。MCP 接続失敗（既存 DEGRADED）は引き続き except で握りつぶすが、validate() の RuntimeError は伝播させて worker 起動を失敗させる（D-03）。

```python
    # Phase 21: MCP client Singleton (D-04)
    # Pitfall 5: MCP server may not be running — graceful degradation
    ctx["mcp_tools"] = []
    ctx["mcp_client"] = None
    mcp_tools_loaded: list = []
    mcp_connected = False
    try:
        from langchain_mcp_adapters.client import MultiServerMCPClient

        mcp_url = os.environ.get("MCP_SERVER_URL", "http://mcp-server:8001") + "/mcp"
        mcp_client = MultiServerMCPClient({
            "copilot-tools": {
                "transport": "streamable_http",
                "url": mcp_url,
            }
        })
        mcp_tools_loaded = await mcp_client.get_tools()
        ctx["mcp_client"] = mcp_client
        mcp_connected = True
        logger.info("[worker] MCP tools loaded: %s", [t.name for t in mcp_tools_loaded])
    except Exception as e:
        logger.warning("[worker] MCP client init failed (DEGRADED): %s", e)
        # mcp_tools remains [] — ToolEnabledSubAgent will fall back to normal SubAgent

    # Phase 24 (MCP-03): ToolRegistry バリデーション
    # try/except の外で実行。RuntimeError は伝播させて worker 起動を失敗させる (D-03)。
    # MCP 接続失敗時 (DEGRADED) はバリデーションをスキップして既存挙動を維持する。
    if mcp_connected:
        from app.orchestrator.tool_registry import ToolRegistry

        registry = ToolRegistry(MCP_TOOLS_CONFIG)
        await registry.validate(mcp_tools_loaded)  # 不一致なら RuntimeError → worker 起動失敗
        logger.info("[worker] ToolRegistry validation passed (%d tools)", len(mcp_tools_loaded))
        ctx["mcp_tools"] = mcp_tools_loaded
```

**注意点:**
- `mcp_connected` フラグで「MCP 接続成功」と「DEGRADED」を区別する（既存 DEGRADED 動作を破壊しない）
- `ctx["mcp_tools"]` への代入はバリデーション成功後に行う
- `from app.orchestrator.tool_registry import ToolRegistry` は startup 内 lazy import（テスト時のモックを容易にする）

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → worker process | `config/mcp_tools.yaml` を worker が読み込む。設定ファイルは信頼境界の内側（リポジトリ管理 + ボリュームマウント read-only） |
| MCP server → worker process | `MultiServerMCPClient.get_tools()` で受け取るツール名リストは外部（mcp-server コンテナ）由来 |

### STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | DoS (D) | `ToolRegistry.__init__` での YAML パース | accept | `yaml.safe_load()` のみ使用（`yaml.load()` は禁止）。設定ファイルは read-only マウントで信頼境界内。意図的に壊された YAML を投入されるシナリオは脅威モデル外。worker は再起動で復旧する。 |
| T-24-02 | Tampering (T) / Information Disclosure (I) | YAML と MCP ツールリストの不一致による無言のドリフト | mitigate | `ToolRegistry.validate()` で双方向 set 差集合チェック → 不一致時に RuntimeError を `try/except Exception` の **外** で raise し、worker 起動を失敗させる（D-03 仕様）。手動デプロイでツール追加し忘れが本番に流出するのを防ぐ。 |
| T-24-03 | Tampering (T) | 任意 YAML パスからの読み込み | mitigate | `MCP_TOOLS_CONFIG` 環境変数のデフォルトを `config/mcp_tools.yaml` に固定。Docker `./config:/app/config:ro` のみマウントされており、コンテナ外からの書き込み不可。 |
| T-24-04 | Spoofing (S) | MCP サーバー由来のツール名信頼 | accept | mcp-server は内部ネットワーク（Docker compose 内）専用で外部公開なし。ツール名は YAML カタログとの完全一致でガード済み（カタログ外のツール名が紛れ込むと起動失敗）。 |
