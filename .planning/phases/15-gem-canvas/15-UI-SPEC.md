## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, tab indicator gap |
| sm | 8px | Button internal padding (vertical), gem chip gap |
| md | 16px | Default element spacing, GemSelector padding, CanvasPane tab padding |
| lg | 24px | Section padding, GemSelector list item padding |
| xl | 32px | Canvas pane min-width step, gem form field gap |
| 2xl | 48px | Canvas pane default width (as percentage basis: 40% of viewport) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Header height: 48px (established — do not change)
- Touch/click target minimum: 44px height for Gem selector chips and tab buttons (WCAG 2.5.5 最小タッチターゲット要件)
- Canvas pane minimum width: 320px (allows readable HTML preview on narrow screens)
- Canvas pane default width: 40% of available chat area width (resizable by user — Claude's discretion, see Interaction Contract)
- Gem chip height: 28px (compact — sits above the chat input bar)

Source: Existing spacing from `MessageArea.tsx` (`padding: '0.6rem 0.75rem'`, `gap: '0.5rem'`), `ChatApp.tsx` (`SIDEBAR_MIN=160`, `SIDEBAR_MAX=480`). Canvas pane width range determined by implementation discretion per CONTEXT.md.

## Component Inventory

These components are created or modified in this phase:

### New: `GemSelector.tsx`

- Compact horizontal chip strip positioned above the chat textarea inside `MessageArea.tsx` (above the input bar, below the message list).
- Shows the currently selected Gem as a highlighted chip and a "No Gem" chip as the first option.
- Clicking a Gem chip selects it — the next new thread will be created with that `gem_id`.
- Clicking the `+` chip opens an inline Gem create form (slide-down panel, not a modal).
- Gem create form fields: Name (text input, max 80 chars), System Prompt (textarea, rows 4, max 4000 chars), Type (radio: "Chat" / "Canvas").
- "Create Gem" button: accent background `#7c6ff7`, white text, `border-radius: 6px`, height 36px.
- "Cancel" button: no background, border `1px solid #d1dbe3`, same height.
- Gem list is fetched via `GET /api/gems` on mount.
- Gem delete: trash icon button on each chip (visible on hover only). Shows inline confirm text "Delete?" with Yes/No — no modal.

### New: `CanvasPane.tsx`

- Right-side panel rendered conditionally inside `ChatApp.tsx` when `canvasApp` state is non-null.
- Layout: flex row — `MessageArea` takes remaining space (at least 60%), `CanvasPane` takes 40% (min 320px).
- CanvasPane has two tabs: "Editor" and "Preview".
  - Editor tab: `<textarea>` (monospace, 13px, `resize: none`, `width: 100%`, `flex: 1`). Auto-resizes to fill pane height.
  - Preview tab: `<iframe srcDoc={html} sandbox="allow-scripts allow-forms" style={{ width: '100%', height: '100%', border: 'none' }}>`. No allow-same-origin to prevent XSS.
- Tab bar: two tab buttons, active tab has bottom border `2px solid #7c6ff7`, inactive tab has background `#f0f0f0` (light) / `#252535` (dark).
- "Save Changes" button: shown in Editor tab only. Calls `PATCH /api/canvas/apps/{app_id}`. Label: "Save Changes". Style: secondary (border, no fill). Height 32px.
- "Deploy" button: always visible in pane header. Calls `POST /api/canvas/apps/{app_id}/deploy`. Label: "Deploy". Style: accent fill (`#7c6ff7`), white text. Height 36px.
- After Deploy: show deploy URL as a clickable link (`/apps/{app_id}/`) with a "Copy URL" button beside it. Color: muted text. Opens in new tab.
- Pane header: shows app name (from `canvas_apps.name`) in 14px semibold. Close button (×) at right to dismiss the pane.
- Loading state within pane: "Saving..." / "Deploying..." text replaces button label during in-flight requests. Button is disabled.

### Modified: `ChatApp.tsx`

- Add `canvasApp: CanvasAppInfo | null` state (initially null).
- When a Canvas response arrives (job result has `type === 'canvas'`), set `canvasApp` from the result payload.
- Render `CanvasPane` as a sibling to `MessageArea` inside the flex row when `canvasApp !== null`.
- No change to `ThreadSidebar` or `MainContainer` structure — CanvasPane is inserted between MessageArea and the right edge.

### Modified: `useChat.ts`

- When job result is parsed and `result.type === 'canvas'`: extract `app_id` and `html` from result payload; pass to parent via callback `onCanvasResponse(canvasApp: CanvasAppInfo)`.
- When job result is a normal text string: behaviour unchanged.
- Add `gem_id: string | null` parameter to the `sendMessage` call payload so the backend receives it on thread creation.

### Modified: `useThreads.ts`

- `createThread()` accepts optional `gem_id?: string | null`.
- Passes `gem_id` in the `POST /api/threads` body.

### New: `useGems.ts`

- Fetches `GET /api/gems` on mount. Returns `{ gems, isLoading, error, createGem, deleteGem }`.
- `createGem(data: GemCreate)` calls `POST /api/gems`.
- `deleteGem(gem_id: string)` calls `DELETE /api/gems/{gem_id}`.

### New: `useCanvas.ts`

- Manages `canvasApp: CanvasAppInfo | null` state.
- `saveCanvas(app_id, html)` calls `PATCH /api/canvas/apps/{app_id}`.
- `deployCanvas(app_id)` calls `POST /api/canvas/apps/{app_id}/deploy`. Returns `CanvasDeployResponse.url`.

### New types in `types.ts`

```typescript
interface GemInfo {
  gem_id: string;
  name: string;
  system_prompt: string;
  type: 'default' | 'canvas';
  created_at: string;

  name: string;
  system_prompt: string;

  app_id: string;

  deployed: boolean;
  deployed_at: string | null;
  created_at: string;
}
```

## Interaction Contract

### GemSelector — Chip Strip

- Chips are rendered as `<button>` elements inside a horizontally scrollable `<div>` with `overflow-x: auto`, `display: flex`, `gap: 8px`, `padding: 4px 12px`.
- "No Gem" chip: always first. Style: border `1px solid #d1dbe3`, border-radius 14px, height 28px, padding `0 12px`. Text: "No Gem". Selected state: border `2px solid #7c6ff7`, background `rgba(124,111,247,0.12)`.
- Gem chips: same dimensions as "No Gem" chip. Text: gem name (truncated at 20 chars with ellipsis). Selected state: same accent border + tint.
- Delete button: trash icon (Unicode `🗑` or text `×`), 16px, visible on `hover` of the chip only. Positioned at right of chip. Clicking shows inline confirm ("Delete?" + "Yes" / "No" buttons as text links).
- `+` chip: always last. Border-radius 14px, `+` character as label. Opens inline create form below the chip strip.
- Inline create form: slide down (no animation required in v1 — `display: block` when visible). Width 100% of the chip strip container. Fields stacked vertically with `gap: 16px`. Create / Cancel buttons at bottom right.
- Gem type radio: "Chat" (default) and "Canvas". Renders as two `<label><input type="radio">` elements side by side. No custom styling beyond native radio.

### CanvasPane — Tab Switch

- Tabs toggle `display: none` / `display: flex` on the content panels — no animation.
- Clicking "Editor" tab: show textarea, hide iframe.
- Clicking "Preview" tab: update `<iframe srcDoc>` with current HTML content (always re-read from state, not from textarea value).
- "Save Changes" button only visible in Editor tab.
- Tab keyboard navigation: `Tab` key moves between tab buttons; `Enter`/`Space` activates tab. Standard browser button behavior — no custom keyboard handler needed.

### CanvasPane — Deploy Flow

1. User clicks "Deploy" button.
2. Button shows "Deploying..." and is disabled.
3. On success: `deployed_at` updates; deploy URL shown below button as `<a href="/apps/{app_id}/" target="_blank">Open app</a>` with a `[Copy URL]` button.
4. On error: show inline error text "Deploy failed. Please try again." in destructive color (`#e05252`) below the button. Button re-enabled.

### ChatApp — Canvas Pane Appearance

- Canvas pane appears immediately when `type === 'canvas'` response arrives (no user action needed).
- Canvas pane can be closed by user via `×` button — sets `canvasApp` to null. Pane can reappear on subsequent canvas responses.
- No persistence of pane open/close state across page reloads.
- On mobile viewports (< 768px): CanvasPane renders below MessageArea (flex direction column), height 50vh. This is Claude's discretion per CONTEXT.md.

### Gem Selection — Thread Scope

- Selected Gem applies to the NEXT new thread created (not the current thread).
- After a new thread is created with a Gem, the Gem chip remains selected (sticky selection).
- Switching to an existing thread: Gem selection UI reflects "No Gem" unless the thread has a known gem (not retrieved in v1 — kept as "No Gem" for simplicity, per Claude's discretion).
- This avoids a round-trip to fetch per-thread gem on every thread switch.

## Accessibility Contract

- All `<button>` elements must have visible focus ring: `outline: 2px solid #7c6ff7`, `outline-offset: 2px`.
- Gem chips are `<button>` elements with `aria-pressed={selected}` to convey selected state to screen readers.
- GemSelector create form: use `<label>` elements wrapping or with `htmlFor` for all inputs.
- Canvas pane tabs: use `role="tab"`, `aria-selected`, `aria-controls` pattern. Tab panel has `role="tabpanel"`.
- `<iframe>` for Preview: add `title="Canvas app preview"` attribute.
- Deploy URL link: `target="_blank"` must include `rel="noopener noreferrer"`.
- Error states: wrap in `role="alert"` so screen readers announce without focus.
- Gem delete confirm: confirm text must be keyboard-accessible (`Tab` to "Yes"/"No" links).
- Touch target minimum: 44px height for all interactive chips, tab buttons, and deploy/save buttons (WCAG 2.5.5 最小タッチターゲット要件).
- Delete button (trash icon): `aria-label="Gem を削除"` required on the `<button>` element to convey purpose to screen readers.
