2. Add DB_URI constant (same pattern as langgraph_handler.py):

4. Wrap the graph build + invoke in an AsyncPostgresSaver context manager. Replace the block:
```python
graph = build_orchestrator_graph(registry, github_token)
initial: AgentState = {"input": prompt, "output": "", "messages": [], "next": ""}
result = await graph.ainvoke(initial)
```

with:
```python
async with AsyncPostgresSaver.from_conn_string(DB_URI) as checkpointer:
    await checkpointer.setup()
    graph = build_orchestrator_graph(registry, github_token, checkpointer=checkpointer)
    config = {"configurable": {"thread_id": thread_id}}

    # Per Pitfall 4 from CONTEXT.md: pass input/output/next each turn.
    # Do NOT pass messages — checkpointer accumulates via operator.add reducer.
    initial: AgentState = {
        "input": prompt,
        "output": "",
        "next": "",
    }
    result = await graph.ainvoke(initial, config=config)
```

CRITICAL PITFALL: Do NOT include `"messages": []` in initial state. The checkpointer accumulates messages via the `Annotated[list[BaseMessage], operator.add]` reducer in AgentState. Passing `"messages": []` each turn would NOT reset history (operator.add appends), but passing it is unnecessary and confusing. Omit it so the checkpointer's accumulated messages are the single source of truth.

CRITICAL PITFALL: Pass `config=config` with thread_id so the checkpointer loads/saves the correct thread state across turns.
