```typescript
interface GemsScreenProps {
  onSelectGem: (gem: GemInfo) => void;
  onBack: () => void;
}
```

**コンポーネント内部の state:**
- `editingGemId: string | null` — 編集中の Gem ID
- `editName: string`, `editPrompt: string` — 編集フォームの値
- `confirmDeleteId: string | null` — 削除確認中の Gem ID
- `showCreateForm: boolean` — 新規作成フォームの表示
- `createName: string`, `createPrompt: string`, `createType: 'default' | 'canvas'` — 作成フォームの値
- `savingId: string | null` — 保存中の Gem ID
- `deletingId: string | null` — 削除中の Gem ID
- `creating: boolean` — 作成中フラグ
- `formError: string | null` — フォーム操作エラー

**`useGems()` から分解して使用:** `{ gems, isLoading, error, createGem, updateGem, deleteGem }`

**各ハンドラー:**
- `handleEdit(gem)` — `editingGemId` をセット、フォームに現在値をセット
- `handleSave(gemId)` — `updateGem(gemId, { name: editName, system_prompt: editPrompt })` を呼び出し（`savingId` で loading 状態管理）、成功後に `editingGemId = null`
- `handleDelete(gemId)` — `deleteGem(gemId)` を呼び出し（`deletingId` で loading 状態管理）、成功後に `confirmDeleteId = null`
- `handleCreate()` — `createGem({ name: createName, system_prompt: createPrompt, type: createType })` を呼び出し（`creating` で loading 状態管理）、成功後に `showCreateForm = false`、フォームクリア

**レンダリング構造:**

## Threat Model

**In scope:** フロントエンドのみの変更。入力バリデーション。XSS。

**Threats identified:**

1. **入力値の未バリデーション（XSS）:** Gem 名・システムプロンプトをレンダリング時に innerHTML に直接入れると XSS リスクがある。**緩和策:** すべての動的テキストは `{gem.name}` などの JSX テキストノード（自動エスケープ）で出力し、`dangerouslySetInnerHTML` は使用しない。

2. **maxLength バイパス:** ブラウザの `maxLength` 属性はクライアント側のみ。**緩和策:** サーバーサイドで既にバリデーション済み（バックエンド変更なし）。フロントエンドの maxLength（name: 80、prompt: 4000）は UX 目的のみ。受け入れ可能。

3. **フォームの二重送信:** ボタンを素早く連打すると `createGem`/`updateGem`/`deleteGem` が重複実行される。**緩和策:** `creating` / `savingId` / `deletingId` の loading state 管理中はボタンを `disabled` に設定する（UI-SPEC.md 仕様通り）。

**Out of scope:** バックエンドの認証・認可（JWT 所有権チェックはバックエンド実装済み）。
</threat_model>
