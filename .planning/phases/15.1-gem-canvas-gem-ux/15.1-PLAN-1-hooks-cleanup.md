# Plan 1: フック拡張・GemSelector 撤去

**Phase:** 15.1 — Gem UX 強化
**Status:** pending
**Wave:** 1
**Depends on:** none
**Autonomous:** true

## Goal

`useGems` フックに `updateGem` 関数を追加し、`useThreads` の引数型を `string` に緩め、ChatApp / SuperChatApp / MessageArea から GemSelector 関連のコードをすべて削除する。このプランは後続プラン（GemsScreen・GemChatApp）が依存する基盤を整える。

バックエンドの `PATCH /api/gems/{gem_id}` と `updateGemApi`（client.ts L135）は既実装済みのため、フロントエンドのフック層を整備するだけで完結する。

## Context

**Locked decisions governing this plan:**
- **D-11:** `useGems` フックに `updateGem(gemId, data)` を追加する（バックエンドの PATCH /api/gems/{gem_id} 実装済み）
- **D-18:** `ChatApp.tsx` から `GemSelector` import・`selectedGemId` state・`onSelectGem` props を削除する
- **D-19:** `SuperChatApp.tsx` から同様に削除する
- **D-20:** `MessageArea.tsx` から `selectedGemId`・`onSelectGem` props を削除し、GemSelector レンダリングを除去する
- **D-21:** `useChat` の `gemId` オプションは残す（GemChatApp が引き続き使用するため）

**Critical pitfalls:**
- GemSelector.tsx を削除するのは、import を外した後（削除してから import を消すとビルドエラー）
- MessageArea の GemSelector ラッパー div は残す（flex レイアウトに必要、RESEARCH.md Pitfall 3）
- useThreads の型を `string` に緩めても既存の ChatApp/SuperChatApp の動作は変わらない（文字列を渡しているだけ）

- `frontend/src/hooks/useThreads.ts`

**Steps:**
- [ ] `frontend/src/hooks/useGems.ts` を読み込む
- [ ] `UseGemsReturn` インターフェースに `updateGem: (gemId: string, data: Partial<GemCreate>) => Promise<GemInfo>` を追加する
- [ ] `import { updateGemApi } from '../api/client';` を既存 import に追加する
- [ ] `createGem` の楽観的更新パターン（setGems で即時反映）を踏襲して `updateGem` を実装する:
  ```typescript
  const updateGem = useCallback(async (gemId: string, data: Partial<GemCreate>): Promise<GemInfo> => {
    const updated = await updateGemApi(gemId, data);
    setGems((prev) => prev.map((g) => g.gem_id === gemId ? updated : g));
    return updated;
  }, []);
  ```
- [ ] `return` 文に `updateGem` を追加する（`{ gems, isLoading, error, createGem, updateGem, deleteGem, refreshGems }`）
