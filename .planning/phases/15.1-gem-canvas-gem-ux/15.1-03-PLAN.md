### Task 2: チェックポイント — Gem UX 全画面 + description/knowledge 動作確認

**Type:** checkpoint:human-verify

**What was automated:**
- Plan 1: gems テーブルへの `description`・`knowledge` カラム追加、API 更新、LangGraph の knowledge 結合ロジック
- Plan 2: `types.ts` 型更新、GemsScreen のフォーム対応・カード表示切り替え

**How to verify:**

ブラウザで `http://localhost:5173/app`（または docker compose のフロントエンドポート）を開き、以下を順番に確認する。

#### A. MenuScreen — Gems カード（D-01〜D-03）
1. MenuScreen に「💎 Gems」カードが表示されている
2. 他のアプリカードとは独立して固定表示されている
3. Gems カードをクリックすると GemsScreen に遷移する

#### B. GemsScreen — 基本 CRUD（D-08〜D-12）
1. Gems が0件のとき「Gems がありません」メッセージが表示される
2. `+ New Gem` ボタンをクリックすると作成フォームが展開する
3. 作成フォームに **Name・System Prompt・Description・Knowledge・Type** フィールドが表示される
4. 以下のデータで Gem を作成する：
   - Name: `テスト Gem`
   - System Prompt: `あなたは親切なアシスタントです。`
   - Description: `テスト用の Gem です`
   - Knowledge: `東京の人口は約1400万人です。`
   - Type: `default`
5. 作成後、カードに Name と Description（`テスト用の Gem です`）が表示されている（system_prompt ではなく description）
6. `Edit` をクリックすると編集フォームに Name・System Prompt・Description・Knowledge フィールドが表示される
7. Back ボタンをクリックすると MenuScreen に戻る

#### C. GemChatApp — チャット起動・knowledge 動作（D-13〜D-17、Todo 7）
1. GemsScreen で作成した Gem の「チャット開始」ボタンをクリック
2. GemChatApp が開き、ヘッダーに「💎 テスト Gem」が表示されている
3. 「東京の人口はどのくらいですか？」と送信する
4. AI が knowledge の情報（「約1400万人」）を踏まえた回答を返す
5. スレッドサイドバーに新しいスレッドが表示される（D-15: `gem-{gem_id}` スコープ）
6. Back ボタンで GemsScreen に戻る（MenuScreen には戻らない — D-07、Pitfall 4 対策）

#### D. GemSelector 撤去確認（D-18〜D-21）
1. MenuScreen から既存アプリ（例: Chat アプリ）を開く
2. ChatApp / SuperChatApp に GemSelector チップストリップが表示されていない
3. MessageArea にも GemSelector 関連の UI が残っていない

#### E. スレッド分離確認（D-15、Todo 8）
1. GemChatApp のスレッドリストに「テスト Gem」のチャット履歴が表示されている
2. ChatApp や SuperChatApp のスレッドリストには「テスト Gem」のスレッドが混入していない
3. ブラウザをリロードして GemChatApp を開き直すと、スレッド履歴が保持されている

**Resume signal:** 上記すべてが正常に動作していれば「承認」と入力。問題があれば発見した問題を具体的に記述する。
