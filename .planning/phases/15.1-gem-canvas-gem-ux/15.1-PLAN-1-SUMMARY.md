# Phase 15.1 Plan 1: フック拡張・GemSelector 撤去 Summary

**One-liner:** `useGems` に `updateGem` 楽観的更新を追加し、`GemSelector` コンポーネントを ChatApp/SuperChatApp/MessageArea から完全撤去した

## What Was Built

後続プラン（GemsScreen・GemChatApp）が依存する基盤として:

1. **`useGems.updateGem`** — `updateGemApi` を呼び出して `setGems` で即時反映する楽観的更新パターン。`createGem` と同じパターンに従う。
2. **`useThreads` 型緩和** — `appId?: 'chat' | 'superchat'` を `appId?: string` に変更。GemChatApp が任意の app_id でスレッドをスコープできるようになる。
3. **GemSelector 完全撤去** — `ChatApp.tsx`・`SuperChatApp.tsx`・`MessageArea.tsx` から `selectedGemId` state、`onSelectGem` props、`GemSelector` import・render をすべて削除。`GemSelector.tsx` ファイル自体も削除。
4. **MessageArea レイアウト保全** — 外側の flex ラッパー `div` は残す（RESEARCH.md Pitfall 3 に従い、chatscope レイアウト干渉を防ぐ構造）。

## Decisions Made

- **updateGem の楽観的更新:** `setGems((prev) => prev.map(...))` パターンは `createGem` の `setGems((prev) => [gem, ...prev])` と整合する。バックエンドが失敗した場合は throw されるため、UI が stale 状態になるリスクは低い。
- **useThreads 型緩和:** `'chat' | 'superchat'` union は GemChatApp が `gem_{gemId}` などの任意文字列を appId として使う可能性に対応できなかった。`string` に緩めることで後方互換を維持しつつ拡張性を確保。
- **GemSelector の撤去先:** GemsScreen（Plan 2）が独立した Gems 管理 UI を持つため、ChatApp 内の inline GemSelector は不要になる。GemChatApp（Plan 3）では gem_id が URL/props 経由で渡されるため、選択 UI 自体不要。
