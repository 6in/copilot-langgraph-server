# Phase 15.1 Plan 3: GemChatApp 新規作成・App.tsx ナビゲーション拡張・MenuScreen Gems カード追加 Summary

**One-liner:** `GemChatApp` コンポーネント新規作成と `App.tsx` 4画面ナビゲーション拡張により `MenuScreen → GemsScreen → GemChatApp` フローを完成させた

## What Was Built

1. **`GemChatApp.tsx`（新規作成 201行）** — Gem 専用チャット画面:
   - `useThreads('gem-${gem.gem_id}')` で Gem 単位のスレッド分離（D-15）
   - `useChat({ gemId: gem.gem_id })` で gem_id をチャットリクエストに含める（D-16）
   - ChatApp.tsx と同パターンの ThreadSidebar + drag handle + MessageArea 構成
   - CanvasPane / GemSelector を持たないシンプル構成（D-17）
   - Gem ヘッダーバー: height 48px、`cardBg` テーマ対応、`← Back` ボタン + `💎 {gem.name}` 表示（UI-SPEC.md 3b 準拠）

2. **`App.tsx` ナビゲーション拡張** — 2画面から4画面へ:
   - `type Screen = 'menu' | 'superchat' | 'gems' | 'gemchat'` に拡張
   - `activeGem: GemInfo | null` state 追加
   - `handleOpenGems / handleSelectGem / handleBackFromGemChat / handleBackFromGems` ハンドラー追加
   - `currentScreen === 'gemchat'` 時に Header へ `onBackToMenu` を渡さない（Pitfall 4 対策）
   - `currentScreen === 'gemchat' && activeGem` 条件でレンダリング（脅威 2 対策）

3. **`MenuScreen.tsx` Gems 固定カード追加**:
   - `onOpenGems: () => void` props 追加
   - `apps.map()` の外側に独立したグリッドセクションとして Gems カード配置（Pitfall 5 対策）
   - ローディング中・空状態・エラー状態のどれでも Gems カードは常に表示

## Decisions Made

- **Screen enum ナビゲーション:** `boolean showGemsScreen` ではなく `type Screen` enum で管理（CONTEXT.md D-04、RESEARCH.md 推奨パターン）。状態の組み合わせ爆発を防ぎ、将来の画面追加に対応しやすい。
- **GemChatApp Back ボタン設計:** App.tsx の Header に `onBackToMenu` を渡さず、GemChatApp 内部の `onBack` コールバックのみで GemsScreen に戻る。Header の Back ボタンが誤って MenuScreen まで戻ることを防ぐ（Pitfall 4 対策）。
- **Gems カードの独立グリッド:** `apps.map()` の外側に独立した `<div>` グリッドとして配置することで、apps ローディング中・空状態・エラー状態のすべてで Gems カードが常に表示される（Pitfall 5 対策）。
