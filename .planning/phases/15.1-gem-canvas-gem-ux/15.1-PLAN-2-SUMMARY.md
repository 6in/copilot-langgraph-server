# Phase 15.1 Plan 2: GemsScreen 新規作成 Summary

**One-liner:** Gem CRUD 管理ハブ画面 `GemsScreen.tsx` を新規作成 — インライン編集・インライン削除確認・新規作成フォーム・SkeletonCard ローディング・空状態を1コンポーネントに収める

## What Was Built

`frontend/src/components/GemsScreen.tsx`（595行）を新規作成:

1. **Gem 一覧カード** — `useGems()` から取得した全 Gem を表示。Gem 名（fontWeight:600）と system_prompt 冒頭50文字（subtitleColor）を表示。
2. **インライン編集フォーム** — Edit ボタンクリックでカード内に展開。Name（maxLength:80）/ System Prompt（maxLength:4000）の2フィールド。最初の入力フィールドに `autoFocus`。「変更を保存」/ 「編集をやめる」ボタン。保存中は `Saving...` に変化してボタンを disabled。
3. **インライン削除確認** — Delete ボタンクリックでカード内に「削除しますか？」+ Yes（#e05252）/ No ボタンを表示。モーダルは使用しない。削除中は `Deleting...` に変化。
4. **新規作成フォーム** — 「+ New Gem」ボタンで展開。Name / System Prompt / Type（default/canvas select）の3フィールド。作成中は `Creating...` に変化し disabled。作成成功後フォームをリセット・非表示。
5. **SkeletonCard ローディング** — `isLoading` 中は pulse アニメーション付き SkeletonCard を3枚表示（MenuScreen.tsx と同一パターン）。
6. **空状態** — Gem がなく作成フォームも非表示の場合「Gems がありません」+ 説明テキストを中央表示。
7. **エラー状態** — フェッチエラー（`role="alert"`, 赤背景）とフォーム操作エラー（formError state）を分離して表示。
8. **テーマ対応** — `useCurrentTheme()` で `screenBg / cardBg / textColor / cardBorder / subtitleColor` を切り替え（MenuScreen.tsx と同一カラートークンパターン）。
9. **セキュリティ** — `dangerouslySetInnerHTML` 不使用。すべての動的テキストは JSX テキストノード（自動エスケープ）で出力。
10. **二重送信防止** — `creating / savingId / deletingId` の loading state 中はボタンを `disabled` に設定。

## Decisions Made

- **useRef の残置:** `autoFocus` 属性で即時フォーカスは実現できるが、将来の命令的フォーカス制御（例: バリデーションエラー後の再フォーカス）に備えて `editNameRef` / `createNameRef` を残す。
- **SkeletonCard のローカル再実装:** MenuScreen.tsx の `SkeletonCard` は同一ファイルの private 関数として実装されている。GemsScreen でも同様に内部実装として再実装し、不要な結合を避けた。
- **formError の単一 state 管理:** 作成・編集・削除のエラーメッセージを `formError` という1つの state で管理。操作ごとに `setFormError(null)` でリセットするため、古いエラーが残るリスクはない。
