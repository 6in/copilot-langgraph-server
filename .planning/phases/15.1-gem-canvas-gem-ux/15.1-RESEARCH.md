## Summary

Phase 15.1 はフロントエンドのみの変更フェーズ。バックエンドは Phase 15 で既に完成している（PATCH /api/gems/{gem_id} 含む）。

主な作業は4分野:
1. **App.tsx ナビゲーション拡張** — `currentScreen` の enum を拡張し、`showGemsScreen` / `activeGem` の2ステートを追加して3画面ルーティングを実現
2. **新規コンポーネント2本** — `GemsScreen.tsx`（Gem CRUD 管理ハブ）と `GemChatApp.tsx`（Gem 専用チャット）
3. **useGems フック拡張** — `updateGem(gemId, data)` を追加（API 関数 `updateGemApi` は client.ts に既実装済み）
4. **GemSelector 撤去** — ChatApp / SuperChatApp / MessageArea から props・state・import を削除

全作業はフロントエンド React の書き換えのみ。TypeScript 型・API クライアント・バックエンド API はすべて既実装済みのため再実装不要。

**Primary recommendation:** ChatApp.tsx を GemChatApp の構造的ベースとして直接コピー＆改変する。App.tsx のナビゲーションは既存の `currentScreen` ステートパターンを拡張し、`'gems'` 画面と `'gemchat'` 画面を追加する。

## Common Pitfalls

### Pitfall 1: useThreads 型シグネチャの不一致
**何が起きるか:** `useThreads('gem-abc123')` が TypeScript エラー `Argument of type '"gem-abc123"' is not assignable to parameter of type '"chat" | "superchat" | undefined'`
**根本原因:** useThreads.ts L26 の引数型が厳密なリテラルユニオン
**回避策:** useThreads の引数型を `string | undefined` に緩める。既存の ChatApp / SuperChatApp の動作は変わらない（文字列を渡しているだけ）。または `as 'chat'` などの型アサーションで回避するが、前者のほうがクリーン

### Pitfall 2: GemSelector 削除タイミング
**何が起きるか:** GemSelector.tsx を削除した後に ChatApp / MessageArea から import が残っているとビルドエラー
**根本原因:** 削除順序の誤り
**回避策:** 必ず「import/使用箇所を削除 → ファイル削除」の順で行う

### Pitfall 3: MessageArea の外側 div 削除
**何が起きるか:** GemSelector の wrapper div（flex コンテナ）も一緒に消すと MessageArea のレイアウトが崩れる
**根本原因:** GemSelector は div 内の最初の子要素として配置されており、div 自体はチャットコンテナの flex レイアウトに使われている
**回避策:** `<GemSelector>` レンダリングブロックのみ削除し、`<div style={{ display: 'flex', flexDirection: 'column', flex: 1, ... }}>` は残す [VERIFIED: MessageArea.tsx L132-142]

### Pitfall 4: App.tsx の Header onBackToMenu 挙動
**何が起きるか:** GemChatApp から Back ボタンで GemsScreen に戻るとき、App.tsx の Header に渡す `onBackToMenu` が MenuScreen に戻ってしまう
**根本原因:** 現在の Header は `onBackToMenu` が設定されていると常に MenuScreen に戻る
**回避策:** GemChatApp → GemsScreen 遷移は GemChatApp 内部の Back ボタン（`onBack` props コールバック）で処理し、Header の `onBackToMenu` とは別に扱う。または Header に `backTarget` を持たせて制御する

### Pitfall 5: MenuScreen の Gems カード配置
**何が起きるか:** Gems カードを `apps.map()` のループ内で生成すると、API 応答が空のとき（apps.length === 0）に表示されない
**根本原因:** MenuScreen.tsx L131 の `!loading && apps.length > 0` 条件ブランチの中にループがある
**回避策:** Gems カードは `apps` 配列とは独立してグリッド内に固定レンダリングする。ローディング中のスケルトンカードには含めない
