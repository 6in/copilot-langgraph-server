    Create `scripts/verify_mcp_worker.py`. This script is designed to be executed INSIDE the worker container via `docker compose exec worker uv run python scripts/verify_mcp_worker.py`. It verifies MCP-01 (connectivity) and MCP-02 (tool list) end-to-end through the Docker network.

    File content:
    ```python
    """Phase 20 smoke test: verify worker → mcp-server MCP connectivity.

    Run inside the worker container:
        docker compose exec worker uv run python scripts/verify_mcp_worker.py

    Verifies:
      - MCP-01: HTTP reachability of mcp-server:8001
      - MCP-02: MultiServerMCPClient.get_tools() returns the 4 Phase 20 stubs
                as LangChain BaseTool instances
    """
    from __future__ import annotations

    import asyncio
    import os
    import sys

    from langchain_core.tools import BaseTool
    from langchain_mcp_adapters.client import MultiServerMCPClient

    EXPECTED_TOOLS = {"ping", "web_search_stub", "db_query_stub", "claude_code_stub"}
    MCP_URL = os.environ.get("MCP_SERVER_URL", "http://mcp-server:8001") + "/mcp"


    async def main() -> int:
        print(f"[verify] connecting to {MCP_URL}")
        client = MultiServerMCPClient(
            {
                "copilot-tools": {
                    "transport": "streamable_http",  # UNDERSCORE (Pitfall 1)
                    "url": MCP_URL,
                }
            }
        )
        tools = await client.get_tools()  # NOT async-with (Pitfall 2)
        print(f"[verify] got {len(tools)} tools")

        # Must all be LangChain BaseTool subclasses
        non_basetool = [t for t in tools if not isinstance(t, BaseTool)]
        if non_basetool:
            print(f"[verify] FAIL: non-BaseTool entries: {non_basetool!r}")
            return 1

        names = {t.name for t in tools}
        print(f"[verify] tool names: {sorted(names)}")
        if not EXPECTED_TOOLS.issubset(names):
            missing = EXPECTED_TOOLS - names
            print(f"[verify] FAIL: missing expected tools: {missing}")
            return 1

        # Invoke ping round-trip to confirm call path
        ping_tool = next(t for t in tools if t.name == "ping")
        result = await ping_tool.ainvoke({})
        print(f"[verify] ping result: {result!r}")
        if "ok" not in str(result):
            print("[verify] FAIL: ping did not return status=ok")
            return 1

        print("[verify] PASS — MCP-01 and MCP-02 verified end-to-end")
        return 0


    if __name__ == "__main__":
        sys.exit(asyncio.run(main()))
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker container → mcp-server container | Internal Docker bridge network; no host port exposed (D-06). Unauthenticated HTTP. |
| Docker host → mcp-server | NOT a boundary in Phase 20 — no ports published to host. Accidentally exposing ports would create a new boundary. |
| mcp-server process → filesystem/network | Stubs do not touch either; boundary is latent until Phase 22/23. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-07 | S (Spoofing) | worker → mcp-server unauthenticated | accept | Docker user-defined network isolates traffic; mcp-server not reachable from host (D-06). 200-user internal app; ASVS L1 does not require mTLS for internal service mesh of this scale. Revisit when mcp-server is split into its own repo/host. |
| T-20-08 | T (Tampering) | docker-compose.yml accidentally publishing mcp-server ports | mitigate | Task 1 acceptance criteria explicitly grep-asserts `ports:` is ABSENT from mcp-server service block. Task 3 human verification includes `curl localhost:8001/health` must fail. |
| T-20-09 | I (Info Disclosure) | langchain-mcp-adapters transport key typo → unexpected SSE fallback leaking session data | mitigate | scripts/verify_mcp_worker.py hard-codes `"streamable_http"` and acceptance criteria grep-asserts it. Pitfall 1 documented in-line in the script comment. |
| T-20-10 | D (DoS) | worker hangs at startup if mcp-server never becomes healthy → blocks arq queue | mitigate | healthcheck has `retries: 5` and `start_period: 15s` — after 65s worker will report dependency failure rather than hang indefinitely. Operator sees failure in `docker compose up --wait`. |
| T-20-11 | E (Elevation) | `uv sync` inside mcp-server container pulls arbitrary transitive deps from PyPI | accept | Same trust model as existing api/worker containers which already run `uv run` against the root pyproject.toml. uv.lock inside mcp_server/ (committed in Plan 01) pins transitive versions. No change to the attack surface beyond adding fastmcp's transitive deps. |
