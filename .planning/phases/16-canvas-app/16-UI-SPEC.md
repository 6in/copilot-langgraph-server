## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Button padding (vertical), element gaps |
| md | 16px | Default element spacing, card header padding (horizontal) |
| lg | 24px | Card padding, section gaps |
| xl | 32px | Screen padding (horizontal) |
| 2xl | 48px | Screen padding (top), section breaks |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Drag handle divider: width 4px (spec contract value; note: existing GemChatApp.tsx uses 5px — implementation MUST update to 4px to align with the 4-multiple scale)
- Header bar height: 48px (existing pattern — GemChatApp.tsx, CanvasPane.tsx)
- Sidebar collapse width: 40px (existing pattern — ThreadSidebar)
- Sidebar default width: 240px, min 160px, max 480px (existing constants from GemChatApp.tsx)
- CanvasPane minimum width: 320px (existing — CanvasPane.tsx)
- CanvasPane default width: 40% of available space (existing — CanvasPane.tsx)
- Tab bar button height: 36px (existing — CanvasPane.tsx)
- Touch target minimum: 48px (height) for all interactive controls (48px is within Apple HIG 44pt tolerance; replaces earlier 44px note)

## Color

Light / dark theme tokens are already defined in `frontend/src/theme.css` and inline in components. New components MUST use the same pattern: declare theme variables from `useCurrentTheme()`, never hardcode values that differ between themes.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#f5f5f5` | `#1e1e2e` | Screen backgrounds |
| Secondary (30%) | `#ffffff` | `#2a2a3e` | Cards, sidebar, headers, CanvasPane background |
| Border | `#dddddd` / `#d1dbe3` | `#3a3a52` | Card borders, dividers, input borders |
| Text primary | `#333333` | `#e0e0e0` | Body text, headings |
| Text secondary | `#666666` / `#a0a0b8` | `#a0a0b8` | Subtitles, descriptions, muted labels |
| Text muted | `#666666` | `#9090a8` | Empty states, dates, placeholders |
| Accent (10%) | `#7c6ff7` | `#7c6ff7` | (see reserved list below) |
| Destructive | `#e05252` | `#e05252` | Destructive actions only |

Accent `#7c6ff7` reserved for:
- Primary CTA buttons (background): "新しいチャットを開始", "チャット開始", "Deploy"
- Active tab underline border in CanvasPane tab bar
- focus-visible outline (`outline: 2px solid #7c6ff7`)
- Inline edit input focus border
- "公開中" badge border and text color
- Sidebar "New Chat" button background (dark mode)

CanvasPane background: always `#ffffff` / `#f0f0f0` (tab bar) — CanvasPane is intentionally light-only in Phase 15; Phase 16 inherits this. Do NOT add dark mode to CanvasPane in this phase.

## Component Inventory

New components required in this phase:

### CanvasScreen (new — `frontend/src/components/CanvasScreen.tsx`)

Reference: GemsScreen.tsx

Layout:
- Full-flex column, `padding: '48px 32px'`, `background: screenBg`, `overflowY: 'auto'`
- Max-width content wrapper: `maxWidth: '640px'`, `width: '100%'`
- Header row: Back button + `<h1>Canvas Apps</h1>` (32px, weight 600)
- Section 1: "Deployed Apps" — card grid, `GET /api/canvas/apps?deployed=true`
- Section 2: "New Chat" CTA button

Deployed app card (CanvasAppCard):
- Same card shell as GemsScreen: `borderRadius: '12px'`, `padding: '24px'`, `border: 1px solid cardBorder`
- Shows: app name (16px, weight 600), deploy URL link (14px, accent color), "Open Chat" button (primary style)
- Click on card: opens CanvasChatApp with that app's thread context

Empty state (no deployed apps):
- Heading: "まだデプロイ済みアプリがありません" (16px, weight 600, muted color)
- Body: "チャットで HTML アプリを生成して Deploy ボタンを押すとここに表示されます" (14px, muted)

### CanvasChatApp (new — `frontend/src/components/CanvasChatApp.tsx`)

Reference: GemChatApp.tsx (direct structural copy with CanvasPane addition)

Layout:
- Outer flex column: `flex: 1`, `minHeight: 0`
- Header bar: 48px height, `borderBottom: '1px solid #d1dbe3'`, Back button + canvas icon + title
- Inner flex row: ThreadSidebar | drag handle | MessageArea | CanvasPane (always visible)

Header bar content:
- Back button: same style as GemChatApp (transparent, `border: '1px solid #555'`, 14px)
- Title: "🎨 Canvas" (16px, weight 600)

CanvasPane integration:
- Always rendered (right side), even before first AI response
- When `canvasApp` is null: show placeholder panel (see empty state below)
- When `canvasApp` is set: render existing `<CanvasPane>` component with full props
- CanvasPane width: 40% of available space (same as Phase 15, no change)
- Drag handle between MessageArea and CanvasPane: 4px wide (see Spacing Scale exceptions)

CanvasPane placeholder (null state):
- `minWidth: '320px'`, `width: '40%'`, same border and background as CanvasPane
- Centered content: icon placeholder + text (see Copywriting section)

### MenuScreen Canvas card (modification — `frontend/src/components/MenuScreen.tsx`)

- Add `onOpenCanvas` prop (same pattern as `onOpenGems`)
- Add FeatureCard: `icon="🎨"`, `title="Canvas"`, `description="AI チャットで HTML アプリを作成・プレビュー・デプロイ"`
- Position: adjacent to Gems card in the fixed feature card grid (insert after Gems, before 討論チャット or rearrange)

## Interaction Contracts

### Drag-to-resize (CanvasChatApp — left/right pane)

- Drag handle: 4px wide, `cursor: 'col-resize'`
- Hover: `background: '#b0c4d8'` (same as GemChatApp sidebar divider)
- Default: transparent
- Min/max constraints for CanvasPane: min 320px, no explicit max (inherited from 40% initial)
- Drag follows existing `onMouseDown` / `window.mousemove` / `window.mouseup` pattern

### Tab switching (CanvasPane — existing, no change)

- Editor tab active: `background: '#ffffff'`, `borderBottom: '2px solid #7c6ff7'`
- Editor tab inactive: `background: '#f0f0f0'`, `borderBottom: '2px solid transparent'`
- No animation on tab switch

### Card hover (CanvasScreen deployed app cards)

- Same hover pattern as MenuScreen FeatureCard: `boxShadow: '0 4px 16px rgba(0,0,0,0.18)'`, `transform: 'translateY(-2px)'`
- Transition: `'box-shadow 0.2s, transform 0.1s'`

### Loading states

- CanvasScreen loading: SkeletonCard x3 (same pulse animation as GemsScreen/MenuScreen)
- CanvasChatApp message loading: existing `<p>Loading messages...</p>` centered pattern

### Focus management

- All interactive elements: `button:focus-visible { outline: 2px solid #7c6ff7; outline-offset: 2px; }`
- Inject via `<style>` tag at component root (existing pattern)

## Accessibility Notes

- All icon-only buttons MUST have `aria-label` (Back button, close button ×, sidebar collapse)
- CanvasPane tab bar: existing `role="tablist"` / `role="tab"` / `aria-selected` pattern — preserve as-is
- iframe preview: existing `title="Canvas app preview"` — preserve as-is
- iframe sandbox: existing `sandbox="allow-scripts allow-forms"` — no allow-same-origin (XSS prevention)
- Error banners: `role="alert"` on all error divs (existing pattern)
- Loading spinner regions: `aria-busy="true"` + `aria-label` on skeleton containers
