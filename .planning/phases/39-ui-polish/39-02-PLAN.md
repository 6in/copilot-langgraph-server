    1. **ヘッダー** (L1-4):
       - `# 0053. Mermaid View デフォルトを Source 固定とする (UIFIX-01)`
       - `**Date:** 2026-05-13`
       - `**Status:** Accepted`

    2. **## Context** (5-8 行):
       - v5.0 期間中の現象記述: 複数 Mermaid ブロックを含む応答で View モード初期描画時に OS-level hang (chromium 全体フリーズ) が発生
       - 現状コード `MermaidBlock.tsx:36` で `useState<'view'|'source'>('source')` により source-default で回避済
       - 根本原因候補 (todo 2026-04-16-mermaid-view-os.md より 5 つ転記): mermaid.render 競合 / SVG style 再計算 / DOM ウォッチャー / 大量 SVG ノード生成 / Monaco Editor との描画衝突
       - 「観察ベースの暫定対応」を Phase 39 で明示的に「恒久対応」へ格上げする意図

    3. **## Decision** (4 項目):
       - `'source'` default を恒久化 (現状コードを維持)
       - View モードは「ユーザーがボタンを押した時のみ」描画 (lazy on-demand)
       - 恒久修正候補 (iframe srcdoc / Web Worker / queue 制御 / mermaid.renderAsync) は v6.1+ `/gsd-spike` で別途検証
       - `MermaidBlock.tsx` 冒頭コメントから本 ADR (0053) を参照する pointer を埋める

    4. **## Alternatives Considered** (4 項目、それぞれ 1-2 文の trade-off 付き):
       - iframe srcdoc: 隔離コンテキストで render — 開発・テスト負荷増、Phase 39 polish には重い
       - Web Worker: SVG 生成をスレッド分離 — Mermaid SDK が main thread 前提、対応未確認
       - 描画 queue 制御: 複数 Mermaid を直列化 — UX 遅延、根本解決でない
       - mermaid.renderAsync (v11+ API): 公式 async API — Mermaid version pin の影響範囲が広い

    5. **## Consequences**:
       - Positive: OS-level hang を確実に回避 (v5.0 から実績あり、UIFIX-01 ROADMAP 合格)、'source' モードで Monaco Editor を即提供できる
       - Trade-offs: 初見ユーザーは View ボタンを押さないと図が見えない、技術負債は v6.1+ に持ち越し

    6. **## Related**:
       - ADR-0037 (Chat UI batch enhancements — Mermaid 関連)
       - ADR-0040 (UI improvements batch — Mermaid 画像コピー)
       - todo: `.planning/todos/pending/2026-04-16-mermaid-view-os.md`

    Pitfall 6 警告: ADR は長文化可、ただし MermaidBlock.tsx 冒頭コメントへの転記は厳禁 (Task 2 で 2 行のみ追記)。
