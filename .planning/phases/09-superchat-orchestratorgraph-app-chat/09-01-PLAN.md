# Plan 09-01: Create app/orchestrator/ module and repo-root agents/menus

**Phase:** 09 - SuperChat OrchestratorGraph App Integration
**Plan:** 01 of 04
**Goal:** Migrate OrchestratorGraph prototype code into `app/orchestrator/` with proper imports and `github_token` threading, and create `agents/` and `menus/` at repo root.

## Context

Phase 8 produced a standalone prototype in `super-agent-sample/src/` demonstrating the OrchestratorGraph + SubAgent + MenuDispatcher architecture. This plan migrates that code into the main app's module structure (`app/orchestrator/`), fixing imports to use the main app's `ChatCopilot` and `CopilotAuthManager`, and threading `github_token` through all classes so multi-user auth works correctly. It also copies `agents/` and `menus/` sample directories to the repo root for the worker to read.

## Notes

- The `github_token` threading is a **required security fix**, not optional. Without it, all users would share the on-disk token from `CopilotAuthManager`. The main app passes per-user tokens from JWT via the job payload.
- `SubAgent.run()` calls `await self._llm.ainvoke(messages)` but does NOT call `await self._llm.close()`. The `ChatCopilot.close()` method should be called when the LLM is no longer needed. The `OrchestratorHandler` (Plan 02) must handle cleanup. For now, each SubAgent creates its own ChatCopilot instance per registry construction -- these are lightweight and will be GC'd. A future optimization could pool them.
- `RouterNode` uses `claude-haiku-4-5-20251001` (a lightweight model for fast routing decisions). Keep this model name as-is.
