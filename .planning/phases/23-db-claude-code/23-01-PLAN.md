import re
_COMMENT_RE = re.compile(r'/\*.*?\*/|--[^\n]*', re.DOTALL)
_ALLOWED_PREFIXES = frozenset(["SELECT", "WITH"])

def is_select_only(sql: str) -> bool:
    cleaned = _COMMENT_RE.sub('', sql).strip()
    body = cleaned.rstrip(';')
    if ';' in body:
        return False
    tokens = body.split()
    return bool(tokens) and tokens[0].upper() in _ALLOWED_PREFIXES
```

         @mcp.tool
         async def db_query(sql: str, pool_name: str = "default") -> dict:
             """PostgreSQL SELECT クエリを実行してデータを返す（DB-01, DB-02）。

             Args:
                 sql: SELECT または WITH ... SELECT 文のみ許可
                 pool_name: db_pools.yaml で定義したプール名
             """
             try:
                 if not is_select_only(sql):
                     return {"error": "Only SELECT queries are allowed"}
                 if pool_name not in _pools:
                     return {"error": f"Unknown pool: {pool_name}"}
                 pool = _pools[pool_name]
                 async with pool.connection() as conn:
                     async with conn.cursor(row_factory=dict_row) as cur:
                         await cur.execute(sql)
                         rows = await cur.fetchall()
                 import json
                 return {"rows": json.loads(json.dumps([dict(r) for r in rows], default=_json_default))}
             except Exception as e:
                 return {"error": f"db_query failed: {e}"}
         ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| エージェント → MCP db_query | LLM が生成した SQL が直接 DB に到達する。LLM 出力は信頼できない（プロンプトインジェクション可能） |
| MCP server → PostgreSQL | mcp-server コンテナから内部ネットワーク経由で postgres コンテナへ接続 |
| docker volume mount | host の `./config/db_pools.yaml` が read-only でマウントされる |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Tampering | db_query SQL 入力 | mitigate | `is_select_only()` ガード（既存 T-18-01 実装をコピー）。SELECT/WITH 以外の文先頭、コメントストリップ後の複文をブロック。エラー時は `{"error": "Only SELECT queries are allowed"}` を返す。|
| T-23-02 | Tampering | CTE write bypass `WITH cte AS (DELETE ...) SELECT ...` | accept | `is_select_only` 単独ではブロックできない。23-RESEARCH.md「Security Domain」記載の通り、`db_pools.yaml` には **読み取り専用 DB ロール** を設定して二重防御することを推奨（実装は db 管理者責任）。本フェーズではドキュメント警告のみ（社内 200 名・低リスク）。|
| T-23-03 | Information Disclosure | DB 接続文字列 (DSN) のログ漏洩 | mitigate | `init_pools()` のログには pool 名のみ出力し DSN は出さない。エラー文字列にも DSN を含めない。|
| T-23-04 | Denial of Service | 巨大 SELECT による DoS | accept | psycopg_pool max_size=5 で同時接続を制限。クエリタイムアウトは未実装（社内利用、低優先度）。将来的に `statement_timeout` を pool 初期化時に設定可能。|
| T-23-05 | Information Disclosure | エラーメッセージから DB schema 漏洩 | accept | 内部利用のみ。エラー文字列に psycopg の error.pgerror が露出するが許容。|
| T-23-06 | Tampering | yaml deserialization (yaml.unsafe_load) | mitigate | 必ず `yaml.safe_load()` を使用。`yaml.load()` (デフォルト unsafe) や `yaml.unsafe_load()` を使わない。|
</threat_model>
