<objective>
Backend foundation for application packages: APP.md definition files, AppRegistry loader, GET /api/apps endpoint, app_id plumbing through chat route and worker handler.

Purpose: Establishes the backend data model and API surface so that applications are defined by files, listed by API, and scoped correctly through the job pipeline. Frontend (Plan 02) consumes these APIs.

**Design rationale (D-07/D-08 REVISED):** AppRegistry is metadata-only at startup -- it scans apps/ and parses frontmatter but does NOT compile graphs or instantiate ChatCopilot. The GitHub Copilot token is per-user (acquired via Device Flow at login), so ChatCopilot cannot be instantiated at server startup before any user has authenticated. Instead, the API route reads the agent list from AppRegistry metadata, passes `agents[]` in the arq job payload, and the worker's OrchestratorHandler builds a per-request SubAgentRegistry filtered to those agents. This avoids the startup-token problem entirely.

Output: Two APP.md files (chat, superchat), AppRegistry module, GET /api/apps route (APP-02 backend), updated chat route with app_id field, updated OrchestratorHandler with app-slug agent filtering, applications table dynamic seeding, unit and integration tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> GET /api/apps | Authenticated users can list available apps |
| client -> POST /api/chat (app_id) | app_id from frontend flows into thread upsert and job payload |
| worker -> APP.md files | Worker reads APP.md from filesystem to resolve agent list |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Information Disclosure | GET /api/apps | mitigate | JWT required via Depends(get_jwt_payload) -- unauthenticated users get 401 |
| T-14-02 | Tampering | POST /api/chat app_id | mitigate | app_id is validated against applications table FK constraint -- invalid slugs fail INSERT |
| T-14-03 | Tampering | APP_DIR path traversal | accept | Path(APP_DIR).glob("*/APP.md") uses single-level glob; directory names cannot contain path separators; APP_DIR is server-controlled env var |
| T-14-04 | Spoofing | OrchestratorHandler APP.md read | accept | Worker reads from server filesystem (APP_DIR env var); not user-controlled input |
| T-14-05 | Denial of Service | Malformed APP.md at startup | mitigate | try/except around frontmatter.load(); malformed files logged and skipped, do not crash startup |
</threat_model>
