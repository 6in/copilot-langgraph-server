<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> GET /api/apps | App listing requires JWT; no unauthenticated access |
| client -> POST /api/chat (app_id) | app_id validated by applications table FK; arbitrary values rejected |
| GET /api/apps response -> MenuScreen | Response is JSON array from trusted backend; rendered as text/emoji, not innerHTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-06 | Information Disclosure | MenuScreen app list | mitigate | JWT required on GET /api/apps; unauthenticated users see AuthPanel, not menu |
| T-14-07 | Tampering | app_id in POST /api/chat | mitigate | FK constraint on threads.app_id -> applications.app_id; invalid slugs cause DB error caught by try/except |
| T-14-08 | Spoofing | AppDefinition.icon XSS | accept | Icon is emoji string rendered as text content (React auto-escapes); no innerHTML or dangerouslySetInnerHTML used |
| T-14-09 | Denial of Service | Large number of APP.md files | accept | Internal tool with ~200 users; APP.md files are developer-controlled; no unbounded user input |
</threat_model>
