## Component Inventory

These components are modified or created in this phase:

### Modified: `MenuScreen.tsx`

- Replace hardcoded `FeatureCard` instances with a mapped list of `AppDefinition` objects fetched from `GET /api/apps`.
- Add loading state: skeleton cards (3 placeholder cards at same dimensions as real cards) while fetch is in flight.
- Add error state: inline error banner below heading (not full-screen replacement).
- Keep `FeatureCard` component intact — no prop API changes, only call-site changes.
- `onNavigate` callback signature changes: receives `AppDefinition` object instead of plain string. `App.tsx` must update the receiver.

### Modified: `App.tsx`

- Add `activeApp: AppDefinition | null` state alongside `currentScreen`.
- `MenuScreen.onNavigate` receives `AppDefinition`; sets `activeApp` and transitions to `'superchat'` screen.
- Pass `appId={activeApp.slug}` and `appName={activeApp.name}` to `SuperChatApp`.

### Modified: `SuperChatApp.tsx`

- Add props: `appId: string` (slug for API/thread scoping) and `appName: string` (display name).
- Display `appName` as subtitle in the chat area header or as secondary text below the main "Copilot Chat" label in `Header`. Do NOT replace the "Copilot Chat" title — add `appName` as a visible sub-label.

### Modified: `Header.tsx`

- Accept optional `appName?: string` prop.
- When `appName` is provided, render it as a secondary label (13.6px / weight 400 / muted color) immediately after the "Copilot Chat" title text. Format: `Copilot Chat · {appName}`.

### New type: `AppDefinition`

```typescript
interface AppDefinition {
  slug: string;
  name: string;
  description: string;
  icon: string;       // emoji or short string
  agents: string[];   // agent folder names
}
```

Source: CONTEXT.md D-06 — `GET /api/apps` returns `{slug, name, description, icon, agents[]}`.

## Interaction Contract

### Menu Screen — App Card Grid

- Layout: CSS grid, `repeat(auto-fill, minmax(180px, 1fr))`, max-width 600px (same as today).
- Cards are `<button>` elements (keyboard navigable, focusable).
- Hover: `translateY(-2px)` + `box-shadow: 0 4px 16px rgba(0,0,0,0.18)` — match existing FeatureCard hover.
- Focus ring: `outline: 2px solid #7c6ff7` (accent color) with `outline-offset: 2px`.
- Click: navigate immediately (no confirm dialog).
- Icon: rendered as emoji string from `APP.md` `icon:` field. Font size 32px (2rem). No fallback icon needed — if `icon` is empty string, render nothing (zero-height icon container, title still visible).

### Menu Screen — Loading State

- Show 3 skeleton cards while `GET /api/apps` is in flight.
- Skeleton card: same dimensions as real card. Background pulsing with CSS animation: `opacity 0.8s ease-in-out` cycling between `0.4` and `1.0`.
- Do NOT show "Loading…" text — let the skeleton carry the loading signal.
- Skeleton uses `Secondary` surface color for the card body (`#2a2a3e` dark / `#ffffff` light) with a slightly lighter shimmer layer.

### Menu Screen — Error State

- Render a small error banner between the subtitle paragraph and the card grid.
- Banner copy: "Could not load applications. Please refresh the page."
- Banner style: `background: rgba(224,82,82,0.1)`, `border: 1px solid #e05252`, `border-radius: 8px`, `padding: 12px 16px`, `color: #e05252` (dark) / same structure in light mode.
- No retry button in this phase (deferred). Refresh guidance is sufficient.

### Menu Screen — Empty State (zero apps returned)

- Heading: "No applications available"
- Body: "Add an APP.md file to the apps/ directory to define an application."
- Style: centered, muted text color (`#9090a8` dark / `#666666` light), font-size 14px (0.875rem).
- No icon/illustration.

### Header — App Name Display

- When `appName` is provided, show `· {appName}` in muted color immediately after "Copilot Chat" title.
- Font size: 13.6px (0.85rem), weight 400, color `#9090a8` (dark) / `#666666` (light).
- Separator `·` is a Unicode middle dot (U+00B7), rendered as plain text with `0.5rem` margin each side.
- Max-width: truncate with `text-overflow: ellipsis` at 160px if app name is very long.

## Accessibility Contract

- All `<button>` elements must have visible focus ring (accent color outline, 2px, offset 2px).
- App icon emoji: `aria-hidden="true"` on the icon container — the card title conveys the accessible name.
- Error banner: `role="alert"` so screen readers announce it without user focus.
- Skeleton cards: `aria-busy="true"` on the grid container while loading; `aria-label="Loading applications"`.
- Empty state: plain `<p>` elements inside the grid area, no special ARIA needed.
- Minimum tap target for cards: 44px height — enforced by `padding: 1.5rem` which produces ~96px+ card height in practice.
