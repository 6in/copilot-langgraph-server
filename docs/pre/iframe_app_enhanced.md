Canvas アプリケーションの拡張方針についてご説明させていただきます

現在、Canvas アプリケーションにおいて、シングル HTML ベースのファイルを作成し、それを用いて開発および プレビューする機能となっております。

これは　シンプル HTML アプリケーションを作成するだけでは、あまり有用性がないです。

そこで iframe で動作する HTML の JavaScript から親フレームへ message を post して、様々な API として呼び出せる機能を追加したいです。

親フレームではメッセージを受信し、そのコマンドとパラメータを Redis に put し、ワーカーにてその処理を行ったあと、Redis に結果を put します。

これは現在、AI lang-graph の呼び出しで実装してる方針と同じです。送信するプロトコルは JSON-RPC と同様に、ワーカープロセスでそれぞれの JSON-RPC のメソッドに紐づく処理を呼び出すという感じで考えています。

このように HTML アプリケーションからさまざまな API を呼び出せる仕組みを用意して、Canvas アプリケーションの便利さを上げたいというのが今回の拡張の内容です。

どのような API があるかというと、

- データベースにクエリを投げられる
- AI の呼び出しができる
- ほかの Web API を呼び出せる

といったものを考えてています。

iframe の親はワーカースレッドを用意してメッセージ処理を動作させます。

また、デプロイしました HTML アプリケーションは HTML をそのまま表示するのではなく、iframe とワーカーで構成された親フレーム内で表示され、ワーカースレッドと postMessage で API の依頼を行います。

ワーカーサービスでは、iframe_app_apiといった識別しで、JSON_PRCとしてのパラメータを受け取り、メッセージ処理を行うメソッドに処理をルーティングしてください。

現状では、データベースにアクセスするQUERYメソッド(SELECT専用)、Copilot-でのAI処理を呼び出すAIメソッド(ワンショットのみ)を用意する。

データベースアクセスは、
- DBプール名
- SQL
- 実行ユーザー
を受け取り、クエリSQLを実行する。クエリ結果はJSONで返却する。

{
    "ressult": true,
    "rows" : [
        { row data },
        { row data },
        { row data },
        { row data },
    ]
}


DBプール名は、予め接続情報を記述したYAMLファイルから取得し、初期化時にDBプールの初期化処理を行う。

AI呼び出しは、
- モデル名
- プロンプト
を受け取り、レスポンスをJSONで返却する

{
    "ressult": true,
    "resposeText" : ""
}
